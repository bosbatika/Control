EYE

A language with its own syntax and data types, compilation of core logic to C, and the ability to connect additional languages and networking components through runtime bridges.

C backendGo / netUDS bridgeType methodsRestartable parts
01

What Is EYE

EYE is designed as a language and runtime environment that can combine multiple languages and components in a single application.

Custom Syntax

Declarations use .Start, methods use dot notation, programs end with end, and types can be abbreviated using ^.

Types with Their Own Methods

A data type contains a value field and a set of methods intended for that type. The compiler binds available method pointers when a variable is created.

Multi-language Architecture

The core logic is generated in C. The built-in module net adds a Go component and a message bridge.

IPC via UDS

Go and the compiler's bridge component exchange messages through a Unix Domain Socket. The C component communicates through standard streams.

Component Recovery

According to the EYE design, individual application components can be restarted after a failure without necessarily restarting the entire application.

Extensibility

Other languages can be connected to the compiler through additional generators and message adapters.

EYE is an evolving project. This page describes the syntax and mechanisms visible in the provided core, as well as architectural capabilities stated by the author.
02

First Example

A minimal program creates an integer, uses a type method, and prints the result.

hello.eye · EYE Example
import stop_import ;

Int chislo.Start = 12 ;

@ printf("Number: %d\n", chislo.value) ;
@ printf("Even? %d\n", chislo.Chet(chislo)) ;

end

In the current implementation Chet returns 1, if the number is even, and 0, if it is odd.

03

Syntax Basics

EYE programs use familiar control structures, but have their own rules for declaring variables and calling external functions.

Declaration
Variables
Int count.Start = 10 ;
Float pi.Start = 3.14159 ;
String title.Start = "EYE" ;
Bool ready.Start = 1 ;
Accessing a Value
The value Field
count.value = count.value + 1 ;
@ printf("%d\n", count.value) ;

Declaration Without an Initial Value: ~

If a variable does not need an initial value at declaration time, the = assignment is replaced by the marker ~. This means: declare the variable without assigning an initial value on the declaration line.

Declaration Without an Explicit Initial Value
Int counter.Start ~ ;
String buffer.Start ~ ;
^ nextCounter.Start ~ ;

Compare: Int counter.Start = 0; sets an explicit initial value, while Int counter.Start ~; declares the variable without such an assignment. After declaration, a value can be assigned through the field .value. Do not confuse this marker with the C bitwise NOT operator.

Conditions and Loops

if and for
Int number.Start = 7 ;

if ( number.value > 0 ) {
    @ printf("positive\n") ;
} ;

for ( int i = 0 ; i < 3 ; i = i + 1 ) {
    @ printf("%d\n", i) ;
} ;

end

The provided core recognizes the control structures if, for and switch. A syntax similar to C is used inside blocks.

Calling C Functions

A call with the prefix @ is passed through to the generated C code. For example:

Calling a Standard Function
@ printf("Hello from EYE\n") ;
@ scanf("%d", &count.value) ;

Data Types

EYE built-in types are represented as C structs. For most types, the primary content is stored in the field value; containers additionally have Size.

EYE TypePurposeMain FieldsMethod Set
IntIntegerint valueConversion, comparison, exponentiation, parity check, length

FileFile and its contentschar* value, char name[100]Write, read, size, append

Int_listArray of integersInt* value, int SizeDelete, allocate, resize, join into a string

Bool_listArray of Boolean valuesBool* value, int SizeDelete, allocate, resize, join into a string
File_listArray of filesFile* value, int SizeDelete, allocate, resize, join names into a string

The .value

For scalar types, it contains the value itself. For String and File it is a pointer to a character buffer; for lists, it is a pointer to an array of elements; for Byte it is a pointer to bytes.

The .Size Field

For Byte and *_list types, it stores the number of allocated/available elements according to allocation and resizing operations.

Internal type: the core C component defines the alias Norm as unsigned char. It is used for Byte elements, but there is no separate EYE type named Norm in the automatic method-binding table.
The method reference for each type follows. Names retain the spelling used in the core, including historical variants Size_stirng, Uper, Redect and Nul_stirng.
05

Methods and Type Abbreviations

When an object is declared using .Start the core zero-initializes the struct and binds the available method pointers for that type. Methods are called through the variable: object.Method(object, ...) or by passing its address if the method signature expects a pointer.

Int Method Example
Int chislo.Start = 12 ;
@ printf("Even? %d\n", chislo.Chet(chislo)) ;
@ printf("Digits: %d\n", chislo.Int_length(chislo)) ;

Int — Integers

Int stores a C int. Methods can convert the number, compare it, raise it to an integer power, check parity, and count its digits.

MethodArguments After the Method NameResult and Purpose
Float_conv(Int value)Converts value.value to float. The internal implementation function is named Int_to_float.
Max_int(Int value, int other)Compares the number with other: returns 1, if the current value is greater; 0, if they are equal; -1, if it is smaller.
Int_to_string(Int value, char buffer[50])Writes the decimal representation of the number to the supplied buffer and returns a pointer to it. The buffer must be large enough for the string and its terminating null character.
Repeat_int(Int value, int exp)Returns the number multiplied by itself exp times: effectively value.value raised to the integer power exp. For exp ≤ 0 the current implementation returns 1.
Chet(Int value)Checks parity. Returns 1 for an even number and 0 for an odd number.
Int_length(Int value)Returns the number of digits in the decimal representation. For 0 returns 1; the minus sign is not counted.
Using Int
Int number.Start = 125 ;
@ printf("float = %f\n", number.Float_conv(number)) ;
@ printf("compare = %d\n", number.Max_int(number, 100)) ;
@ printf("even = %d\n", number.Chet(number)) ;
@ printf("digits = %d\n", number.Int_length(number)) ;

Float — Single-precision Numbers

Float stores float value. Methods convert it to an integer or string and compare it with another value.

MethodArgumentsResult and Purpose
Conv_int_min(Float value)Converts Float to int using a standard C cast: the fractional part is discarded toward zero.
Conv_int_max(Float value)Returns the value rounded to the nearest integer using roundf.
Float_to_string(Float value, char buffer[50])Writes the value to the buffer using the format %f and returns a pointer to the buffer (typically six digits after the decimal point according to printf rules).
Max_float(Float value, float other)Comparison: 1 — greater, 0 — equal, -1 — less.
Using Float
Float price.Start = 12.75 ;
@ printf("truncated = %d\n", price.Conv_int_min(price)) ;
@ printf("rounded = %d\n", price.Conv_int_max(price)) ;
@ printf("compare = %d\n", price.Max_float(price, 10.0)) ;

Double — Double-precision Numbers

Double stores double value. Its method set is similar to Float, but operates on the double-precision type.

MethodArgumentsResult and Purpose
Conv_int_min(Double value)Converts the value to int discarding the fractional part toward zero.
Conv_int_max(Double value)Rounds the value to the nearest integer using round.
String_double(Double value, char buffer[50])Writes the decimal representation using sprintf(..., "%f", ...). The internal implementation function is named Double_to_string.
Max_double(Double value, double other)Comparison: 1 — greater, 0 — equal, -1 — less.

String — Strings

String contains char* value. This is a C string terminated by the character \0. Case-conversion and search methods operate directly on the string buffer.

MethodArgumentsResult and Purpose
Size_stirng(String* value, int size)Allocates a buffer of the specified size, copies the old contents (up to size - 1 bytes) and appends a terminating \0. The spelling Size_stirng is the exact API field name; the implementation is named Size_string.
String_to_int(String value)Converts the beginning of the string to int using the C function atoi.
String_to_float(String value)Converts the beginning of the string to float using atof.
Lower(String* value)Converts Latin letters in the string to lowercase. Modifies the buffer itself.
Uper(String* value)Converts Latin letters in the string to uppercase. The field is named Uper, while the bound C function is Upper.
Contains(String value, char* substring)Searches for a substring using strstr: returns 1, if found, and 0, if not found.
Repeat_string(String value, int count)The function pointer field exists in the String struct, but the method is not connected in the checked binding table or core implementation. Do not call it until an implementation is added.
Using String
String title.Start = malloc(128) ;
strcpy(title.value, "Eye Language") ;
@ title.Lower(&title) ;
@ printf("%s\n", title.value) ;
@ printf("contains = %d\n", title.Contains(title, "eye")) ;
@ printf("as int = %d\n", title.String_to_int(title)) ;
For Size_stirng, Lower, and Uper, the signature accepts a pointer to String, so a direct call to the C function must pass the object address: &title. For conversions and Contains, pass the struct itself.

Bool — Boolean Values

Bool contains only the field _Bool value. In the provided core implementation, scalar Bool has no declared method pointers or automatic method bindings. Use the value directly in conditions.

Using Bool
Bool ready.Start = 1 ;
if ( ready.value ) {
    @ printf("ready\n") ;
} ;

File — File Operations

File contains a pointer value to the file contents and an array name[100] containing the file name/path. File methods accept File*, that is, the address of the struct.

MethodArgumentsResult and Purpose
Write_file(File* value)Opens name in write mode "w", writes the string from value and closes the file. Returns the number of characters written, or -1, if the file could not be opened.
Read_file(File* value)Opens the file, gets its size using Size_info, allocates a buffer, and reads data using fgets. Returns 0 on successful reading and 1 on error.
Size_info(File* value)Returns the file size in bytes using ftell; returns -1 if the file cannot be opened.
append(File* value, char text[])Opens the file in append mode "a" and appends the supplied C string to the end. No value is returned.
Calling File Methods
File logFile.Start ~ ;
strcpy(logFile.name, "app.log") ;
logFile.value = "EYE started\n" ;
@ logFile.Write_file(&logFile) ;
@ printf("size = %ld\n", logFile.Size_info(&logFile)) ;
The "w" mode used by Write_file overwrites the existing file. To append to the end, use append.

Byte — Byte Buffer

Byte stores Norm* value and the number of bytes in Size. In the core, Norm is defined as unsigned char. All methods accept a Byte* pointer.

MethodArgumentsResult and Purpose
Delete_byte(Byte* value)Frees the buffer, sets value = NULL and Size = 0.
Nul_byte(Byte* value, int count)Frees the previous buffer, allocates count zero-initialized bytes using calloc and stores the count in Size.
Redect_byte(Byte* value, int count)Resizes the buffer using realloc. This is the API name; the bound implementation function is named Redirect_byte.
Allocating a Byte Buffer
Byte payload.Start ~ ;
@ payload.Nul_byte(&payload, 256) ;
@ printf("bytes = %d\n", payload.Size) ;
@ payload.Delete_byte(&payload) ;

Lists: Int_list, Float_list, Double_list, Bool_list, String_list, File_list

Lists are structs with a pointer to the value array and a Size field. Each list type follows the same general method pattern: free memory, allocate a new array, resize it, and join the elements into a single string.

List TypeArray ElementMethodsJoin Output
Int_listIntDelete_int, Nul_int, Redect_int, Join_intComma-separated numbers
Float_listFloatDelete_float, Nul_float, Redect_float, Join_floatNumbers in %f format, comma-separated
Double_listDoubleDelete_double, Nul_double, Redect_double, Join_doubleNumbers in %f format, comma-separated
Bool_listBoolDelete_bool, Nul_bool, Redect_bool, Join_bool1 or 0 format, comma-separated
String_listStringDelete_string, Nul_stirng, Redect_string, Join_stringComma-separated strings
File_listFileDelete_file, Nul_file, Redect_file, Join_fileComma-separated file names
Method FamilyArgumentsBehavior
Delete_*(List* value)Frees the array, sets the pointer value to NULL and resets Size to 0.
Nul_*(List* value, int count)Frees the old array and allocates a new zero-initialized array of count elements using calloc. Updates Size.
Redect_*(List* value, int count)Resizes the existing array using realloc; on success, updates the pointer and Size. The internal implementation functions are named Redirect_*.
Join_*(List* value)Creates and returns a new String struct with comma-separated elements. Memory for the resulting string is dynamically allocated.
Int_list Example
Int_list numbers.Start ~ ;
@ numbers.Nul_int(&numbers, 3) ;
numbers.value[0].value = 10 ;
numbers.value[1].value = 20 ;
numbers.value[2].value = 30 ;
String joined.Start ~ ;
joined = numbers.Join_int(&numbers) ;
@ printf("%s\n", joined.value) ;
@ free(joined.value) ;
@ numbers.Delete_int(&numbers) ;
The parameter count is the number of elements/bytes, not the last index. After Nul_* valid indices range from 0 to Size - 1. The result of Join_* is a newly allocated string; it should be freed after use.

Repeated Type Shorthand: ^

The symbol ^ repeats the last explicitly declared type. This is declaration shorthand, not an exponentiation operator.

The ^ Operator
Int first.Start = 10 ;
^ second.Start = 20 ;
^ third.Start ~ ;

Float pi.Start = 3.14159 ;
^ radius.Start = 2.5 ;
^ scale.Start ~ ;
After changing types, specify the new type explicitly: for example, after a group of Int write Float, and subsequent ^ will repeat Float.

Declaration Marker Without Assignment: ~

If an initial value is not required, use = in a .Start declaration instead of the equals sign. This option is useful when the field will be populated later or memory/an array will be prepared by the corresponding method. ~.

Explicit and Deferred Initialization
Int readyValue.Start = 5 ;
Int inputValue.Start ~ ;
String text.Start ~ ;
Int_list items.Start ~ ;

inputValue.value = 42 ;
text.value = malloc(128) ;
items.Nul_int(&items, 10) ;
For pointer-based types (String, File, Byte, and lists), memory and pointers must be prepared before use. Declaring a variable with ~ does not allocate a buffer automatically.
06

Imports and C Functions

The import section is located at the beginning of the program and ends with the marker import stop_import.

Import Order
import net ;
import my_library ;

@ int twice(int x) {
    return x * 2 ;
} ;

import stop_import ;

Int value.Start = 21 ;
@ printf("%d\n", twice(value.value)) ;

end
  • import my_library; includes the contents of the import file in the generated C code.
  • import net; enables the additional Go networking runtime component.
  • import stop_import; closes the import section and begins the C program body.
  • Declarations prefixed with @, that appear before stop_import, are added to the list of C functions.
Place functions that must be available as C declarations before import stop_import. After this marker, write the executable program code.
07

Networking Module net

The built-in module lets you define an HTTP server in EYE. The compiler generates Go wrappers, while user-data processing can be performed in C.

EYE HTTP Server Skeleton
import net ;
import stop_import ;

String packet.Start = malloc(4096) ;

for ( ; ; ) {
    if ( fgets(packet.value, 4096, stdin) == NULL ) {
        break ;
    } ;

    if ( strncmp(packet.value, "!value ", 7) == 0 ) {
        printf("$text/plain; charset=utf-8!Hello! This is the EYE server\n") ;
    } else {
        printf("$ok\n") ;
    } ;

    fflush(stdout) ;
} ;

net_http_server web.Start = "/" ;
net_http_server web.Query ;
net_http_server web.Write ;
net_http_server web.Stop ;
net_http_server web.Where ;
net_http_server web.Listen = "127.0.0.1:8080" ;

end

net_http_server Methods

ConstructRole
.StartStarts an HTTP handler and sets its path, for example "/".
.AddressPasses the client address.
.QueryPasses the URL and query parameters.
.MethodPasses the HTTP request method.
.HeaderPasses HTTP headers.
.ValueUserPasses the request Referer.
.FormPasses form data.
.BytePasses the request body as a byte string.
.CookiePasses request cookies.
.WriteRequests the response generated by the C component and writes it to the HTTP response.
.StopCloses the handler body.
.WhereCloses the handler registration call.
.ListenStarts the HTTP server at the specified address.

Within a single handler, request-reading and response-sending methods are placed between the handler's opening and closing statements. The order of calls matters.

08

How Languages Communicate

The key idea behind EYE is that not every component has to be written in the same language. The runtime connects processes through different communication channels.

HTTP / GoReceives a request and creates a message
UDSUnix Domain Socket between Go and the bridge
Core BridgeForwards data between channels
stdin / stdoutC process input and output streams
C / EYEExecutes user logic

Important: C Does Not Connect to UDS

C receives messages through standard input (`stdin`) and sends responses through standard output (`stdout`). UDS is used on the Go and core-bridge sides.

Response Marker $

The bridge recognizes C lines that begin with $, removes the prefix, and sends the contents back to Go through UDS.

HTTP Response Protocol

To process a request, C reads a line from stdin. A regular request can be acknowledged with $ok. For the response command !value C sends the content type and body separated by !.

Response Format from C
if ( strncmp(packet.value, "!value ", 7) == 0 ) {
    printf("$text/plain; charset=utf-8!Response from EYE\n") ;
} else {
    printf("$ok\n") ;
} ;
fflush(stdout) ;
`Write` on the Go side sends the request `!value`, receives a string in the format `Content-Type!body`, sets the HTTP header and writes the body to the client.

Connecting Other Languages

The project architecture allows additional languages to be connected to the compiler. A new language requires a corresponding generator/launch adapter and an agreed message protocol. UDS is one method of inter-process communication. The presence of UDS alone does not mean an arbitrary language can be connected automatically without an adapter.

09

Fault Tolerance and Component Restart

The EYE author describes a recovery model conceptually similar to the Elixir approach: individual parts of an application can be restarted after a failure.

Component Isolation

An application can be organized into separate components so that a failure in one component does not necessarily stop the entire application.

Restart

The runtime is designed to recover failed components by restarting them, rather than only restarting the entire process.

External Processes

An architecture with multiple languages and IPC channels makes it possible to divide responsibilities among separate processes.

This description reflects the stated EYE concept. The provided source does not contain a complete user-facing syntax for a supervisor tree, restart strategies, or restart-intensity policies. Therefore, no invented example of such directives is included here.

The similarity to Elixir is conceptual: the idea of recovering individual components. This does not imply OTP compatibility or an identical supervisor implementation.

Compilation and Execution

The compiler reads the .eye, generates C code and, when import net is enabled, also generates a Go component.

Compiler Prompts

  1. Output C file name.
  2. An additional command or commands, if needed.
  3. Program execution time.
  4. Source file name `.eye`.
  5. Go file name, if `import net`.

In the current implementation, GCC is used to build C; the Go toolchain is used for the networking component. When mathematical functions are used, the core links the math library.

Launch modes and bridge behavior depend on the core version. Use matching compiler and runtime versions; do not mix core files from different development iterations.
